# .Agents.md — Kairos Agent Guide

Read this file before changing the project.

## Project

Kairos (`io.github.yks777.kairos`) is a single Omarchy plugin with `service` and `bar-widget` kinds. The `bar-widget` loads `Panel.qml` internally via a `Loader` (per the Omarchy plugin development documentation). It is written in QML and pure JavaScript. All plugin strings, comments, labels, documentation, and errors must be in English. User-authored content is exempt.

## Source and installation

- **Source of truth:** `/home/user/kairos/` in the current workspace. Keep edits in this directory.
- **Installed copy:** `~/.config/omarchy/plugins/io.github.yks777.kairos/`.
- Never use symlinks inside the plugin folder. Synchronize files as regular files.
- During development, keep `omarchy.clonedFrom: "omarchy.clock"` in `manifest.json`. Remove it only before marketplace publication.

## Invariants

- `Service.qml` is the only owner of mutable plugin state. `BarWidget.qml` and `Panel.qml` read service properties and call service methods; they must not keep competing copies.
- Timers derive from wall-clock timestamps such as `deadlineMs`, `startedAtMs`, and `accumulatedMs`. `tickVersion` only refreshes bindings and is never the time source.
- `Model.sanitizeState()` must never throw. Corrupt state must be backed up as `state.json.corrupt-<timestamp>` before a safe blank state is written.
- Mutations use `saveSoon()` (800 ms debounce) or `saveNow()` for critical transitions. `bump()` alone never persists.
- `BarWidget.qml` loads `Panel.qml` internally via a `Loader` (per Omarchy documentation). `Panel.qml` is not loaded by the shell panel loader.
- All colors and spacing come from `qs.Commons` theme tokens and `Style.space()`. Icons are Nerd Font glyphs only; never use emoji.
- Do not add symlinks. Market APIs must remain public/keyless. Email is the explicit authentication exception: secrets belong only in Secret Service via `secret-tool`, never in state files, logs, or argv. Social connectors remain optional local adapters and must report unavailable capabilities without fabricating data.

## Validation ritual

Every `.qml` or `.js` edit is complete only after these steps:

1. Validate the plugin manifest and layout:
   ```sh
   PLUGIN_DIR="$HOME/.config/omarchy/plugins/io.github.yks777.kairos"
   omarchy plugin validate "$PLUGIN_DIR"
   ```
2. Lint the shell entry points:
   ```sh
   qmllint -I "$OMARCHY_PATH/shell" \
     "$PLUGIN_DIR/BarWidget.qml" \
     "$PLUGIN_DIR/Panel.qml" \
     "$PLUGIN_DIR/Service.qml"
   ```
3. Run pure-logic and helper-script tests:
   ```sh
   node --test tests/
   python3 -m unittest discover -s tests -p 'test_*.py'
   ```
4. Synchronize source to the installed directory using regular-file copies, then restart the shell:
   ```sh
   omarchy restart shell
   sleep 6
   omarchy-shell shell ping
   ```
5. Open the affected view through IPC, capture a screenshot with `grim`, and inspect it visually. Test both sides of any changed conditional.
6. Return the environment to its prior state and confirm with `omarchy-shell io.github.yks777.kairos status`.

The current development workspace may not have Omarchy or a display session installed. If a command is unavailable, record that limitation explicitly; do not claim runtime validation or a visual check that was not performed.

## State-file safety

Never edit `state.json` while the shell is running and then immediately restart it. Back up first, stop the shell before injecting test data, restart, and verify both the file and IPC output. Restore any test data and verify the final state before finishing.
